# Agent 翻译向导

你可以把下面的提示词交给能读取文件、执行终端命令并向你提问的 coding agent，例如 Claude Code、Codex、Cursor 或 OpenCode。Agent 自己阅读文档、安装工具、生成配置、检查接口，然后翻译。你只需要回答问题，不需要先读配置手册或手工编辑 TOML。

这不是 attx 内置的聊天窗口或 `config wizard` 命令。问答由你的 Agent 完成，实际翻译仍走 attx CLI。如果 Agent 没有本地文件、命令执行或安全密钥输入能力，它必须说明缺少的能力，不能假装已经配置成功。

## 复制这一段给 Agent

不必先填路径、API 或模型名。知道输入路径时可以加在最后；不知道其他参数就让 Agent 带你选择。

```text
请帮我使用 attx 完成翻译。我不想手动安装、查配置文档或编辑 TOML，
请你自己阅读项目文档，逐步提问并替我完成配置，然后执行翻译。

项目：https://github.com/kaecho/attx

先检查本机是否已经有 attx 或项目目录。读取 README.zh-CN.md、
skills/attx/SKILL.md、skills/attx/references/agent-setup.md、
skills/attx/references/cli-command-contract.md，以及 docs/zh 下的
install.md、usage.md、configuration.md。格式和审校细节按需再读。
本机没有项目时，从项目仓库或官方发行包取得这些文件。
使用真实 CLI 的 --help 核对命令，不编造 config/setup 等不存在的命令。
优先使用适合本机系统与架构的发行版；需要系统权限、全局改动或覆盖已有安装时先说明。

配置缺失、失效，或者我要求重新配置时，启动问答向导。
每轮只问一个主题，相关参数可放在同一轮。每一步都先解释：
1. 这项是什么，解决什么问题；
2. 它会影响哪些能力、质量、速度、费用或风险；
3. 推荐怎样配置，以及为什么；
4. 我需要回答什么，接受推荐值时怎样回复。
不要只抛出 worker_count、rpm 等术语让我自己查。
已经能从已有配置、文件或我的回答中确定的值，不要重复问。

先询问翻译接口的服务和 API 地址，解释 OpenAI 兼容 Chat Completions。
然后询问 API Key，通过 Agent 支持的安全输入或终端隐藏输入接收。
你负责把密钥直接写入本机 setting.toml，并在支持权限的系统上保护配置文件。
不要让我手工编辑 TOML；不要让我把完整密钥贴到普通聊天中；
不要回显密钥、打印整份私密配置、写入日志/任务单/JSONL/Git，
也不要把密钥放进翻译提示词或 API 地址。
可以在不展示内容的情况下复用我授权使用的已有本机密钥。
没有安全输入能力时，说明需要何种安全输入或隐藏终端能力，不能伪造 Key。

继续询问服务商实际支持的模型 ID、输入文件或游戏目录、源语言、目标语言、
全量或试译范围、费用/限额要求、文风与专名习惯。
解释并发、RPM、批次大小、上下文、重试与自动修复，并给出建议。
区分程序默认值与建议值：默认 worker_count=8、rpm=60；
首次使用且服务限额未知时可建议 worker_count=2、rpm=30，不要说这是程序默认。
其他默认值是 batch_chars=2500、max_context_items=6、context_chars=1200、
retry_count=3、retry_delay=2、repair_rounds=2。让我可以一并接受推荐值。
模型不支持或不需要的 temperature、reasoning_effort、max_tokens、stream、extra，
解释后保持省略或默认，不为配置完整而强行发送。

解释术语表如何统一人名等专名，以及构建会产生额外模型费用，询问是否开启；默认关闭。
说明未知文本格式最多三轮 Profile 推断可能增加费用，必要时让我选择 --no-infer。
说明本地经验总结默认开启且不调用模型，LLM 经验复核默认关闭。
具体翻译风格通过 CLI learn note 设置，专名放 glossary，变量或控制串放 preserve。
不要私自启用额外付费功能、放宽保护规则、批量批准 skip 规则。

你负责生成并校验 setting.toml，显示不含密钥的配置摘要。
配置完成后使用显式 --config 路径运行 doctor --json --ping，
读 llm.configured 和 ping 的实际值，不能只看退出码或顶层 ok。
401/403 或永久配置错误时停止请求，只问需要修正的项，不轮换 Key 或无限重试。

确认输入、语向、范围和费用选择后，使用 attx run 的共享流水线开始任务，
按配置进行有限修复。正常翻译与带备份写回属于这次请求，
包括 RPG Maker 原地写回，不再额外问一次写回许可。
如果我选试译、预览、限额或不写回，就严格遵守；
不擅自使用 --allow-partial，也不删除工作区或手改输入/数据库。
未知格式先用本地探测或声明式 Profile，不执行模型生成的任意提取/写回脚本。

每个阶段简要解释正在做什么、结果意味着什么、下一步是什么。
结束时报告实际输出路径、工作区、成功/待译/未解决数量和检查结果。
退出 2 或 blocked/needs_attention 不算全量成功；不能承诺一次翻译完美。

请先读取文档并检查环境，再开始第一轮必要的提问。
```

想给出任务范围，可以追加：

```text
输入是 D:/Games/My Game，日文翻译为简体中文。
请先带我配置接口和参数，再做正常全量翻译与带备份写回。
```

## 每一步 Agent 应该怎样解释

| 步骤 | 这是什么、能做什么 | 推荐与应问的问题 |
|---|---|---|
| 安装与环境 | attx 是本地单二进制 CLI，Agent 用它提取、翻译、检查和写回 | 已有安装先复用；否则选本机发行包。只有源码构建才需要 Rust 1.89+。问确实无法确定的安装位置或权限选择 |
| API 地址 | `base_url` 是服务地址前缀，程序追加 `/chat/completions` | 问服务名称及兼容地址，不要把完整方法地址重复追加。原生 Anthropic/Gemini 协议需要兼容网关，`provider_type` 不能替你转换协议 |
| API Key | 凭据用于接口鉴权，不是翻译内容 | 问用户准备如何安全提供或复用已有本机凭据。用安全输入/隐藏终端，Agent 直接落入配置，不在普通聊天中收集或回显 |
| 模型 | `model` 是服务商的实际模型 ID，决定语言能力、输出质量与价格 | 询问可用模型及预算，不猜不存在的 ID。不了解服务支持的可选参数时，先省略这些字段 |
| 输入与语向 | 文件或目录决定适配器，`src`/`dst` 决定提取和翻译方向 | 问实际路径与语言；默认 ja→zh 只适用于日文到简体中文。已有工作区不能随意换语向 |
| 范围与费用 | 全量、试译、限额和不写回是不同任务范围 | 让用户选择全量或样本；试译可用 `--limit N --no-writeback`。没有价格和 token 证据时不编造总价 |
| 并发与限速 | worker 是并行 HTTP 批次数，RPM 是每分钟开始请求的节奏 | 默认 8/60；服务限额未知时建议先 2/30，稳定后再调整。不要默认设 RPM=0，不把 worker 当作模型线程或质量等级 |
| 批次与上下文 | chars/items 控制每批原文量，context_chars 控制前后邻文的总预算 | 推荐先 2500 字符、6 单元、1200 上下文字符。不是模型上下文窗口，也不是每条文本必有全文上下文 |
| 重试与修复 | 请求级重试处理暂时失败，repair 轮处理剩余机械问题 | 默认重试 3 次、等待 2 秒、额外修复 2 轮。设修复轮 0 可节省追加调用，但仍可能有未解决项。鉴权错误不靠提高次数修好 |
| 术语表 | 统一人名、地名等专名；构建增加 LLM 调用 | 默认关闭。长篇或多角色作品可建议开启并说明费用；门槛 10 个含词单元、最多 200 词、每批最多注入 30 词，构建最多抽样 40 源批次 |
| 风格与保护 | prompt note 表达文风，glossary 表达专名，preserve 保留变量与控制串 | 询问真正需要的敬称、人物口吻与既定译名，不要求用户先写正则。过宽保护会遮住正文，不能拿它隐藏漏译 |
| 未知格式 | 本地 Auto 不收费；没有匹配时声明式 Profile 推断可能收费 | 根据任务说明最多三轮推断和只输出副本的限制；用户可关闭推断。二进制或含糊语法不能当普通文章翻译 |
| 检查与执行 | doctor 查配置/连通性，run 执行共享管线并报告结果 | 读取实际 ping 字段，正常执行带备份写回，不强制再次问许可。部分输出要明确选择，剩余问题必须报告 |

模型可选项不需要一上来逐个填写。默认未指定温度时翻译调用用 0.3，JSON 辅助调用用 0.0；推理强度、输出上限默认不发送，stream 默认 false。Agent 应解释用途，让用户选择“保持默认”，而不是为每个空字段编造值。完整键表仍在[配置参考](configuration.md)。

## 一轮问答的样子

Agent 可以这样开口：

> 我已经读过安装和配置说明。下一步需要确定翻译服务，它负责接收原文并返回译文，也决定可用模型和费用。attx 要求 OpenAI 兼容 Chat Completions。你使用哪家服务？请给服务地址前缀，不要附上 `/chat/completions` 或密钥。

接着是密钥步骤：

> API Key 是这家服务的鉴权凭据。建议通过安全输入框或隐藏终端提供，我会直接写入本机配置，不会回显。你想安全输入一个新 Key，还是授权我复用已有配置中的 Key？

参数步骤应提供选择，而不是让用户查缩写：

> 并发影响同时发送多少批请求，RPM 控制请求频率，不直接决定译文质量。程序默认是 8 个 worker、每分钟 60 次。你还不知道服务限额，我建议首次用 2/30。要采用建议值、保留程序默认，还是填写已知额度？

用户可以回答“采用建议，其他可选参数默认”。Agent 记录这些选择，生成配置，并继续询问尚未确定的输入、语向和范围。示例中没有真实密钥。

## 用户做什么，Agent 做什么

用户提供服务凭据和输入路径，选择模型、语向、范围，以及是否承担额外功能费用。Agent 负责读取文档、安装或找到程序、正确写入配置、校验、执行命令和解释结果。

隐藏输入是密钥传输方式，不是人工配置步骤。Agent 可以准备安全输入过程，但 attx 本身没有交互式配置命令。所用 Agent 若不能处理安全输入或与用户交互的隐藏终端，应在这一步说明限制，不能让普通聊天变成秘密存储，也不能假装工具支持不存在的功能。

## 已配置或中断后

配置已可用时，跳过重复的 API/Key/模型问答，只补充缺失的任务选择。用户说“重新带我配置”时才重新开启相应步骤，不未经授权覆盖其他客户端或已有密钥。

中断后复用同一工作区。Agent 先解释 `status` 和 `review` 的真实状态，再续译或做有限修复；不要删库从头开始，也不要无限重跑。正常写回不再提第二次许可，但备份、源文、锚点和完整性检查仍执行。
