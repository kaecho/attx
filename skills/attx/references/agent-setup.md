# Agent 问答配置协议

适用：用户第一次使用 attx、配置缺失/失效，或明确要求由 Agent 重新带着配置。目标是用户只回答问题，Agent 阅读文档、找到或安装 CLI、生成配置并运行任务。已有有效配置直接复用，只补充缺失信息。

这份协议不新增 `attx config`、`attx setup` 或交互式安装命令。问答和安全输入由宿主 Agent 的能力提供；实际操作使用当前 CLI、文件工具和必要的本机安装方式。

## 先读，再问

先定位项目或官方发行包。必须读取：

- `README.zh-CN.md` 或 `README.md`；
- `skills/attx/SKILL.md` 和 `references/cli-command-contract.md`；
- 人类文档 `docs/zh/install.md`、`docs/zh/usage.md`、`docs/zh/configuration.md`，或者对应语言版本；
- `docs/zh/agent-translation.md` 的复制提示词与步骤说明；
- 遇到特殊格式、保护规则、术语、费用或质量问题时，按需读对应参考。

检查真实 CLI 的 `--help`、`formats` 和非敏感 `doctor --json` 输出。不可从记忆猜命令、可选字段或版本。无法读取本机文档时，读取本项目的官方文档，不要求用户先自行学习配置。

常规安装由 Agent 负责。先复用 PATH、发行包或已有构建；需要安装时说明目标路径与平台/架构，优先普通用户目录的发行版。涉及 sudo、系统级安装、覆盖已有软件或无关目录变更时另行取得权限，不把用户要求配置翻译工具扩成任意系统修改。

## 每轮输出格式

每轮一个主题，相关参数可以成组；避免一次列出几十个没有解释的字段。

```text
当前步骤：<主题>
这是什么：<用日常语言解释>
能做什么与影响：<能力、质量、速度、费用或风险>
建议：<具体推荐值与原因；注明与程序默认值的区别>
请回答：<明确问题，允许接受推荐/默认或提供自己的值>
```

已经从配置、用户回答、命令或文档确定的值，不重复提问。用户说“其他可选项默认”时，保留真实默认或省略对应字段，并解释结果。保持已选值的状态，失败后只返回需要修正的主题，不从头重复整个向导。

## 问答主题与建议

### 1. 服务与端点

询问服务名称、OpenAI 兼容 Chat Completions 的 `base_url`，或者是否使用已经配置的客户端。解释 attx 会追加 `/chat/completions`，不能重复这个后缀。`provider_type` 仅作记录，不能把原生 Anthropic/Gemini 协议转为兼容协议。

不把 API Key 放入 URL。远程服务优先 HTTPS，本地无鉴权服务按其实际接口配置。没有端点信息不能编造一个看似可用的地址。

### 2. API Key

明确询问用户要安全提供新 Key，还是授权复用已有本机配置里的 Key。解释它用于接口鉴权，不是翻译内容。普通聊天不是密钥输入框。

按宿主实际能力处理：

1. 有不进入普通聊天、工具回执或日志的安全输入时，使用它。
2. 否则准备用户可操作的隐藏终端输入，关闭回显，让本机过程直接写入配置。不要通过 stdout 将 Key 返回给模型。
3. 两种方式均不可用时，说明缺少安全输入/交互终端能力，先补齐宿主能力。不能伪造 Key，也不要把“用户手工编辑 TOML”设为正常向导路径。

Agent 负责生成配置，并正确处理 TOML 字符串转义、私有目录/文件权限和已有内容。Unix 上私密配置使用0600或私有目录，权限要在写入秘密前建立；Windows 按用户范围保管，不任意改变其他文件 ACL。密钥只落入本机配置，不能进 prompt、JSONL、任务单、报告、Git 或日志。显示摘要时只写“Key 已配置”，不显示原值或尾码。


服务明确无需鉴权时，`api_key` 可配置为空字符串并跳过秘密输入；字段仍需存在。不要编造 dummy Key 来冒充已配置的远程鉴权。
用户已经主动提供敏感内容时，不回显、不复制到其他记录；仅按授权写入本机配置并提醒其避免在普通聊天中继续发送。不得借机读取或复用无关服务的凭据。

### 3. 模型与可选请求项

询问服务商实际支持的 `model` ID，以及质量/费用偏好。不能猜模型名或自动切换到未经选择的服务。客户端默认可命名 `main`，多客户端时问本次选择，不覆盖其他客户端。

解释可选参数，不要求用户为每个空字段填写值：

| 参数 | 解释与默认选择 |
|---|---|
| `temperature` | 随机程度。省略时翻译调用0.3、JSON辅助调用0.0；不支持该字段的模型按服务要求处理 |
| `reasoning_effort` | 部分模型的推理档位，未配置不发送；仅在服务支持且用户选择时设置 |
| `max_tokens` | 输出上限，不是输入批次大小；默认不发送。需要 `max_completion_tokens` 的服务使用已说明的 `extra` |
| `stream` | 是否读取 SSE，默认 false。它不会把不完整输出当成成功 |
| `extra` | 高级请求覆盖表，默认空。不能替换 messages，不装密钥、不为了完整配置增加未经确认的字段 |
| `timeout` | 单次请求超时，默认600秒，实际至少30秒；不能靠延长超时修复401或错误模型 |

### 4. 输入、语向与风格

询问实际文件/游戏目录、源语言、目标语言。说明默认 ja→zh 只是日文到简体中文的默认，不是所有作品的正确语言。输入可通过本地文件/目录选择提供，不让用户为了界面方便把密钥或整部作品粘贴进聊天。

询问确实重要的文风、敬称、人物口吻与既定专名。将具体风格通过 `learn note` 写到作品工作区，专名通过 glossary 管理，不直接改经验文件。对中文目标，不能默认将假名尾屑当作风格留下。

### 5. 范围与费用

询问全量、指定样本、限额、只提取、只翻译不写回等范围。没有价格/token证据不报虚构总价或完成时间。试译可使用 `--limit N --no-writeback`，但不强制所有完整任务先试译再问一次。

说明全文翻译会发送原文、相关邻文、术语和风格 note 到用户选择的服务。用户已经给定明确范围和预算时，不重复取得同一授权。

### 6. 速度、批次和上下文

解释 worker 是并发 HTTP 批次数，RPM 是请求节奏；它们不是模型内部线程数，也不是译文质量等级。

真实默认值：worker8、RPM60、batch_chars2500、max_context_items6、context_chars1200。首次使用且限额未知，可以建议 worker2、RPM30，必须说明这是保守建议，不是程序默认。额度已知时沿用允许值，不默认 RPM=0。

解释 chars/items 是每批原文量与单元数，context_chars 是每个请求前后邻文的总字符预算，不是模型上下文窗口。允许用户一并接受建议值。

### 7. 重试与自动修复

默认 retry_count3、retry_delay2秒、repair_rounds2。解释前者限制每轮请求重试，后者限制额外机械修复轮；降低次数省费但可能留下更多问题。401/403或永久配置错误立即停止，不能用加次数或轮换 Key 解决。

有限流程结束仍有问题就报告，不在 Agent 外层无限重启命令重置预算。

### 8. 术语、保护、学习和未知格式

说明术语表用于统一专名，构建额外调用模型，问是否开启，默认关闭。默认 min_occurrences10个含词单元、max_terms200、inject_limit30；构建最多40源批次，不保证全文覆盖。

本地经验总结默认 true、不花模型费用；LLM经验复核默认 false，不能擅自开启。会删除提取内容的 skip 学习规则仍由用户按索引批准，Agent 不得 approve-all。

保护变量/控制串优先内置规则，不要求用户先写正则。特殊语法靠证据确定，不放宽规则来掩盖漏译。Auto本地探测不收费，无匹配时 Profile推断最多三轮且可能付费，说明 `--no-infer` 选择。未知二进制或含糊语法不执行任意模型生成代码。

## 生成、检查、执行

Agent 写 `setting.toml`，必要时保留用户已有客户端。不要以手工改数据库或源代码替代配置。后续命令使用同一个明确的 `--config` 路径，避免当前目录变化选中别的文件。

展示不含秘密的摘要：输入、语向、客户端/模型、endpoint、范围、并发、限速、重试/修复、额外付费功能、输出行为。询问用户尚未决定的范围或费用选择，而不是再问已经明确授权的写回。

运行一次必要的 `doctor --json --ping`，检查 `llm.configured` 和实际 ping。它会发极小请求，不能仅以exit0或顶层ok判定连接。出现致命鉴权/端点/模型问题，停止请求并解释需要修改的项。

可运行后使用共享 `run`。必要的作品风格 note 可以先通过 init和learn note落入工作区，再run同一身份。正常任务包括带备份写回，不另设强制写回许可。遵守预览、样本、限额及 no-writeback 选择；部分输出需明确选择 allow-partial。

每阶段解释当前动作和状态。结束报告真实路径、工作区、已完成/待译/未解决项，以及是否真实写回。blocked、needs_attention、exit2、dry-run都不能冒充全量成功。重启使用同一工作区，不删除已有进度，不承诺一次翻译完美。
